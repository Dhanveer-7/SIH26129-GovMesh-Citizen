GOVMESH – SIH26129
DEPARTMENT 1 – REVENUE & FOREST DEPARTMENT
SIMULATED DEPARTMENT SYSTEM – MVP REQUIREMENTS
============================================================

PURPOSE
-------
Department 1 represents the Revenue & Forest Department in the
GovMesh interoperability demonstration.

Its purpose in the MVP is to demonstrate:
- Department-specific service processing
- Citizen/application verification
- A heterogeneous government system connected through GovMesh
- REST/JSON integration
- Workflow status updates
- Data validation
- Consent-aware data exchange
- Failure/exception reporting
- Auditability

IMPORTANT:
This is a simulated department system for the SIH prototype.
It must NOT be presented as a live integration with the Government
of Maharashtra unless formal authorization/API access exists.


============================================================

7. REST API INTEGRATION
============================================================

Department 1 should deliberately use:

Protocol:
REST

Payload:
JSON

Suggested endpoints:

POST /api/v1/revenue/address/verify
GET  /api/v1/revenue/application/{id}
POST /api/v1/revenue/application/{id}/approve
POST /api/v1/revenue/application/{id}/reject
POST /api/v1/revenue/application/{id}/request-info
GET  /api/v1/revenue/health

Example response:

{
  "applicationId": "GM-2026-000124",
  "status": "VERIFIED",
  "department": "REVENUE"
}


============================================================
8. DEPARTMENT-SPECIFIC DATA MODEL
============================================================

Use a deliberately different internal schema from GovMesh.

Example:

Revenue system:
citizen_name
house_no
street
village
taluka
district
proof_id
verification_status

GovMesh canonical model:
citizen.name
citizen.address
citizen.address.district
documents[]
verification.status

GovMesh must perform the transformation.


============================================================
9. CONSENT VERIFICATION
============================================================

Before processing:

Department checks:
- Consent exists
- Consent is valid
- Purpose matches request
- Data scope is allowed
- Recipient is authorized
- Consent is not expired/revoked

If invalid:
Do NOT process.

Return:
CONSENT_INVALID

============================================================
20. SUCCESS CRITERIA
============================================================

The SIH evaluator should clearly see:

1. GovMesh sends a standardized request.
2. Revenue system receives it through REST/JSON.
3. Revenue uses its own internal data model.
4. GovMesh maps canonical data to Revenue format.
5. Officer verifies the request.
6. Department sends structured result.
7. GovMesh updates the unified citizen timeline.
8. Full audit trail is retained.

FINAL MESSAGE:
"Revenue is an independent system. GovMesh interoperates with it
without replacing it."
