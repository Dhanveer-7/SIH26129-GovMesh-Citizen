GOVMESH – SIH26129
CITIZEN APPLICATION
COMPLETE FEATURES, SCREENS & REQUIREMENTS
============================================================

Purpose:
This document defines the complete Citizen App requirements for the
GovMesh SIH26129 prototype, based on the project solution documents and
the discussed MVP/demo flow.

Core principle:
The Citizen App is NOT another replacement government portal.
It is the citizen-facing entry point into GovMesh, which coordinates
existing/ simulated government systems through interoperability,
consent and workflow orchestration.

Core citizen journey:
LOGIN
  -> HOME
  -> DESCRIBE SERVICE / SELECT SERVICE
  -> IDENTIFY REQUIRED DEPARTMENTS
  -> VIEW DATA + PURPOSE
  -> GIVE CONSENT
  -> UPLOAD DOCUMENTS
  -> VALIDATION
  -> WORKFLOW START
  -> UNIFIED TIMELINE
  -> NOTIFICATIONS
  -> COMPLETION / ACTION REQUIRED


============================================================
1. LOGIN & AUTHENTICATION
============================================================

MUST HAVE

1.1 Welcome Screen
- GovMesh logo/name
- Short explanation:
  "One citizen request. Multiple government systems. One coordinated
   workflow."
- Login button
- Register button
- Help / privacy link

1.2 Citizen Registration
For the MVP, use simulated identity verification.
Production identity integration requires government authorization.

Fields:
- Full name
- Mobile number
- Email (optional)
- Citizen reference ID / simulated government ID
- Password/PIN if used by the prototype

1.3 Login
Recommended MVP:
- Mobile number
- OTP
- Optional app PIN

Alternative prototype:
- Username + password
- OTP simulation

1.4 Secure Session
- JWT/OIDC-style authentication
- Session timeout
- Logout from all devices
- Token refresh
- Secure storage of authentication tokens

1.5 Re-authentication
Require additional authentication for sensitive actions such as:
- Giving consent
- Revoking consent
- Changing profile information
- Submitting sensitive documents
- Confirming important workflow actions

============================================================
4. NATURAL-LANGUAGE SERVICE REQUEST
============================================================

This is one of the important intelligent features.

Citizen can type or speak a request in natural language.

Example:
"I have moved to a new address and want to update my government records."

The AI/intent module:
- Detects the user's intent
- Identifies the likely service
- Suggests relevant government departments/services
- Extracts useful entities such as address
- Does NOT autonomously execute government actions

Output:

Detected request:
ADDRESS CHANGE

Potentially affected services:
1. Revenue Department
2. Food & Civil Supplies Department
3. Rural Development Department

Button:
[Review & Continue]

IMPORTANT:
AI is assistive only.
The deterministic workflow engine and approved policy rules control
actual service execution.

32. WHAT THE CITIZEN SHOULD NOT SEE
============================================================

Do NOT expose:
- Raw API keys
- JWT contents
- Internal service URLs
- SOAP/XML payloads
- Queue names
- Database details
- Internal exception stack traces
- Infrastructure IP addresses
- Internal security rules
- Sensitive officer-only information

Citizen sees understandable outcomes.
Officer dashboard sees operational details.

============================================================
35. DATA MINIMIZATION RULE
============================================================

Citizen App must NOT ask for every possible personal detail.

Only request information required for the selected service.

Example:

If Food Department only needs:
Name + Address + verification result

Do not send:
Unrelated documents
Unrelated personal information
Unrelated service history


============================================================
36. DESIGN PRINCIPLE: SINGLE TIMELINE
============================================================

The most important UX promise:

"One request -> one application ID -> one timeline."

Citizen should not need:
Portal A -> Portal B -> Portal C

Instead:

Citizen App
    ->
GovMesh
    ->
Multiple departments
    ->
One unified timeline


============================================================
37. DESIGN PRINCIPLE: AI IS ASSISTIVE
============================================================

AI can:
- Understand natural-language request
- Extract document information
- Suggest relevant services
- Suggest schema mappings
- Detect possible inconsistencies

AI cannot independently:
- Approve government service
- Change authoritative records
- Grant consent
- Transfer data without consent
- Make legal decisions

Final execution:
Policy + consent + deterministic workflow.
