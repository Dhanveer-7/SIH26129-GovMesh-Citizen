GOVMESH – SIH26129
DEPARTMENT 3 – RURAL DEVELOPMENT & PANCHAYAT RAJ
SIMULATED DEPARTMENT SYSTEM – MVP REQUIREMENTS
============================================================

PURPOSE
-------
Department 3 represents the Rural Development & Panchayat Raj
Department.

Its role is to demonstrate integration with a LEGACY-STYLE system.

Recommended simulated integration:
CSV/File + SFTP

This gives the MVP three different integration patterns:

Department 1:
REST + JSON

Department 2:
SOAP + XML

Department 3:
Legacy CSV/File + SFTP

3. PRIMARY MVP USE CASE
============================================================

LOCAL ADDRESS / RURAL SERVICE RECORD UPDATE

GovMesh sends the approved standardized information to Department 3.

Instead of a modern API, the simulated legacy system receives
a structured CSV file.

Example:

application_id,citizen_name,address,district,verified
GM-2026-000124,XXXXX,XXXXX,Chennai,true

============================================================
5. FILE INGESTION
============================================================

Department system should:

1. Detect incoming file
2. Verify file name
3. Validate file structure
4. Validate headers
5. Parse records
6. Validate required fields
7. Detect duplicates
8. Process valid records
9. Reject invalid records
10. Generate result file

Example:

INBOUND:
GM_2026_000124.csv

OUTBOUND:
GM_2026_000124_RESULT.csv


============================================================
6. FILE VALIDATION
============================================================

Validate:
- Required columns
- Column order
- Data types
- Date formats
- Address fields
- Application ID
- Duplicate records
- Empty values

Invalid records should be placed into an exception queue.


============================================================
7. BATCH PROCESSING
============================================================

Department 3 should support batch processing.

Example:

100 records received

Valid:
96

Invalid:
4

Processed:
96

Rejected:
4

GovMesh receives the processing summary.


============================================================
8. CONSENT VALIDATION
============================================================

Consent metadata should accompany the transfer.

For the MVP, this can be represented through:
- Signed metadata
- Consent reference
- Manifest file
- Secure transfer metadata

Department verifies:
- Application ID
- Consent ID
- Purpose
- Allowed data fields
- Validity


============================================================
9. MANIFEST / METADATA
============================================================

A file transfer should include metadata.

Example:

File:
GM_2026_000124.csv

Application:
GM-2026-000124

Consent:
CONSENT-00124

Purpose:
Rural service record update

Created:
2026-08-30T10:15:00

Checksum:
<generated checksum>

This demonstrates integrity checking.


============================================================
10. FILE INTEGRITY
============================================================

Use checksum/hash to detect corruption.

Example:

Sender:
SHA-256 = ABC123...

Receiver:
SHA-256 = ABC123...

Result:
FILE INTEGRITY VERIFIED


============================================================
11. DUPLICATE FILE DETECTION
============================================================

Detect:
- Same file uploaded twice
- Same application repeated
- Same checksum
- Same application ID

If duplicate:
Do not process twice.

Return:
DUPLICATE_FILE


============================================================

============================================================

============================================================
22. SUCCESS CRITERIA
============================================================

The evaluator should see:

1. Department 3 uses a legacy-style interface.
2. No modern REST API is required by the simulated department.
3. GovMesh transforms canonical data into CSV.
4. Secure file transfer occurs.
5. File integrity is checked.
6. Records are validated.
7. Invalid records enter an exception queue.
8. Valid records are processed.
9. Result is returned to GovMesh.
10. Citizen sees a unified workflow status.

FINAL MESSAGE:
"GovMesh can integrate modern APIs, enterprise services and
legacy file-based systems through reusable adapters."
